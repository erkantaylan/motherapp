# tmux tool: sending text to a session (2026-11-10, sub-agent: tmux send)

The tmux page has a Send box and there is `tmuxctl send` (`tools/tmux/src/send.ts`). Follows
`2026-10-20-tmux-send-enter.md` and answers part of its open question. Measured on Claude Code
2.1.322 and tmux 3.6a, in a private tmux server with a real `claude` (Haiku) and with
`bash --norc` and `zsh -f`.

## Lessons

- [local] What doesn't work in Claude Code is the **line feed**, not the timing.
  `send-keys -l -- $'text\n'` leaves the text in the input box, and `$'a\nb'` arrives as `ab`:
  the `\n` neither submits nor breaks the line. The Enter key (`send-keys Enter`, a carriage
  return) submits. → Never put `\n` in what goes through `send-keys -l`.
- [local] On this version the pause could not be made to matter. All of these submitted: text
  and `Enter` in one tmux invocation; two calls 0 ms apart with 1500 characters; and the process
  stopped with `kill -STOP`, text and Enter sent, then `kill -CONT`, so both arrived in one
  read (25 and 1550 characters). → The tool keeps the inbox's 200 ms anyway: it costs nothing,
  the user asked for a pause, and older versions were reported to need it. Don't read the 200 as
  a measured minimum.
- [local] Several lines: `set-buffer -b <name> -- <text>` then `paste-buffer -p -d -b <name> -t
  %N`. Claude shows the lines in its box (a long one as `[Pasted text #1 +420 lines]`), bash and
  zsh show them at the prompt without running anything, and the one Enter afterwards submits or
  runs all of it once. With and without `-r` looked the same in Claude. A program that didn't ask
  for bracketed paste (`cat`, `sh`) gets each line break as an Enter.
- [local] A long single line typed as several `send-keys -l` calls shows up in Claude as one
  `[Pasted text]` per call. → Anything over one command's worth goes through the buffer too.
- [both] A tmux command line over 16 KiB fails with `command too long` (16 000 characters passed,
  20 000 didn't). → Long text is built up with `set-buffer`, then `set-buffer -a`, 2000
  characters a call.
- [both] The trailing `;` rule from the inbox lesson holds on 3.6a and for `set-buffer` as well:
  `ls;` must be sent as `ls\;`, and `find … \;` as `find … \\;`.
- [both] `display-message -p -t '$99:' '#{pane_id}'` for a session that doesn't exist is exit 0
  with an empty value, like the missing pane in the inbox lesson. → Match the output (`%N`) and
  treat anything else as "gone".
- [both] Keys sent to a pane in copy mode are copy-mode commands (`q` leaves it, others move or
  search). → `#{pane_in_mode}` is read with the pane id, and the send is refused.
- [local] The Bash tool here eats one level of backslashes in a command, also inside a
  `python3 - <<'EOF'` heredoc: `"\\;"` reached the file as `"\;"`, so a JavaScript test quietly
  sent the unescaped text and "proved" the wrong thing. → Put code with backslashes in a file
  with the Write tool, or build the character (`String.fromCharCode(92)`), and grep the result.
- [local] The headless browser may only save screenshots inside the repo or `.playwright-mcp/`;
  a bare file name lands in the repo root as an untracked file. → Save under `.playwright-mcp/`
  and delete it afterwards.
- [local] A private core for looking at a page needs `MOTHERAPP_TRAY=off` besides
  `MOTHERAPP_NOTIFY=off` (and `MOTHERAPP_RELEASE_URL=off` keeps it off the network), plus
  `TMUX_TMPDIR=<short dir>`; `/run/user/<uid>/<name>` is short enough for the socket.
- [local] The real `claude` in the test server answers with the user's account: every submitted
  test prompt is a real turn (the status line showed 93% of the weekly limit used). → Test with
  "Enter not pressed" where that proves the point, and submit only the few that must be.

## Open

- A LAN client was not opened in a browser for this: the Send box is hidden by the same branch
  that hides the preview (`LOCAL_ONLY` from `view`), and the core's refusal of `localActions` is
  covered by the core's tests, but nobody looked at it from a second address.
- Claude Code versions before 2.1.322, and what a 200 ms pause does when Claude is mid-turn
  with a queued message, were not tried.
- The text is briefly visible in the process list as an argument of `tmux`, as with the inbox
  tool. `load-buffer -` from stdin would avoid it for pastes; the runner has no stdin today.
- Sending only Enter (an empty box) is refused. If the user wants to answer a permission
  prompt from the page, "1" with "Press Enter" off works; a bare Enter button would be new.
