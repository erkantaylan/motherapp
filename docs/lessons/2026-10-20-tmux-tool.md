# tmux tool and the button copy/confirm vocabulary (2026-10-20, sub-agent: tmux tool, issues #6 and #8)

Built `tools/tmux/` (`tmuxctl`) and added `copy` and `confirm` to `ButtonWidget`.

## Lessons

- [cloud] `apt-get update && apt-get install -y tmux` works in the container as root and gives
  **tmux 3.4**, the same version as the machine. → Test against the real binary
  (`tools/tmux/test/real-tmux.test.ts`, skipped without tmux) on a private socket
  (`tmux -S <tmpdir>/sock`), and kill that server in `after()`.
- [both] Without a UTF-8 client, tmux 3.4 replaces every non-printable or non-ASCII byte in
  `-F` output with `_`, **including the tab separators** of the format in issue #6. The container
  has no `LANG`, and a systemd user service may not either. → Every call passes `tmux -u`
  (force UTF-8). With it, tabs and `é🚀` come through unchanged.
- [both] tmux escapes session names when they're created: a tab becomes the two characters `\t`,
  a newline `\n`, a backslash `\\`, and `:`/`.` become `_`. The name `list-sessions` prints is
  exactly what `-t '=<name>'` matches (checked with `back\slash`). → Copy and target the listed
  name as-is, and never unescape it.
- [both] "No server" has three forms: `no server running on <sock>` (socket file left behind),
  and `error connecting to <sock> (No such file or directory)` for both "no socket" and "no
  socket dir" (the tool tells those apart with `fs.existsSync` on the directory). All three
  exit 1 and mean an empty list. Any other `error connecting` (e.g. Permission denied) is an error.
- [both] Use `-t '=name'`, never a bare name: a session named `$1` is otherwise read as the
  session id `$1`, and a missing `foo` prefix-matches `foo2`. The copied command is
  `tmux attach -t '=<name>'` for the same reason. The page kills by session id (`$N`), which
  is also exact and survives a rename made since the last poll.
- [cloud] Web tests run under the root tsconfig (no DOM lib, no jsdom). → Keep widget logic
  DOM-free (`web/src/button.ts`: click order, click-time templates, clipboard fallbacks) and
  pass the dialog and clipboard in from `renderer.ts`.
- [both] List rows interpolate their widgets once, at row creation. Text that must follow the
  row (a confirm naming a renamed session) has to be interpolated at click time. `confirm` and
  a string `copy` are, and everything else stays as it was.
- [cloud] `scripts/test-install.sh` checked "no wrapper for the demo tool" by counting files in
  `~/.local/bin` (== 1), so any second tool with `bin` broke it. → It now checks that no `demo`
  wrapper exists.

## Open

- Whether the systemd user service sees the user's tmux server: same uid, `TMUX_TMPDIR` unset
  in both the service and the user's shells, so both use `/tmp/tmux-<uid>/default`. The tool
  logs `socket` and `uid` at start ("tmux tool serving"), and the page says which socket it
  looked at when it finds no server.
- Whether `pane_current_command`/`pane_current_path` in `list-sessions` (active pane of the
  current window) is what the user wants on the second line.
- Clipboard fallbacks (`execCommand`, the Ctrl+C dialog) haven't been seen in a real browser,
  only in unit tests with fakes.
