# Tray icon (2026-11-10, sub-agent: notifications stage 3 of 3)

The core now shows a tray icon through a Python helper (`core/tray/motherapp-tray.py`,
supervised by `core/src/tray.ts`; DESIGN.md § 3 "Tray icon"). Measured on Ubuntu 24.04, GNOME
Shell 46 on Wayland, `ubuntu-appindicators` enabled, python3-gi 3.48, AyatanaAppIndicator3 0.1.

## Lessons

- [both] **A private core started by hand now needs `MOTHERAPP_TRAY=off`** next to
  `MOTHERAPP_NOTIFY=off`. Only `node --test` turns it off by itself. While this was being built,
  another agent's private core (same checkout, port 7399, `MOTHERAPP_NOTIFY=off` only) picked up
  the new code and put a second motherapp icon in the user's real tray. `npm run dev` sets it off.
- [local] The running service's environment had only `XDG_RUNTIME_DIR` and
  `DBUS_SESSION_BUS_ADDRESS` (`tr '\0' '\n' </proc/<MainPID>/environ`): no `WAYLAND_DISPLAY`,
  no `DISPLAY`, although `systemctl --user show-environment` has both. The unit starts at
  login before GNOME imports them. → `sessionEnv()` in `tray.ts` fills them in from
  `show-environment` for the helper and for `xdg-open`. GTK 3 alone would have coped
  (`Gtk.init_check` succeeds without either variable, GDK tries `wayland-0`), a browser may not.
  The tmux tool's Open (`terminator`) gets no such help and may be affected after a reboot:
  not checked.
- [local] How to check an indicator without seeing the screen:
  `gdbus call --session --dest org.kde.StatusNotifierWatcher --object-path /StatusNotifierWatcher
  --method org.freedesktop.DBus.Properties.Get org.kde.StatusNotifierWatcher
  RegisteredStatusNotifierItems` lists `:1.N@/org/ayatana/NotificationItem/motherapp`. On that
  bus name, `org.kde.StatusNotifierItem` has `IconName` (the PNG's absolute path, which the
  extension accepts), and `<path>/Menu` speaks `com.canonical.dbusmenu`: `GetLayout 0 -1 []`
  gives labels, `enabled` and `toggle-state`; `Event <id> "clicked" <variant> 0` clicks an item.
  gdbus's own parser chokes on `GetLayout`'s empty `as`; a ten-line Gio script works.
- [local] No screenshot of the panel is possible from a session like this one:
  `org.gnome.Shell.Screenshot` answers "Screenshot is not allowed", `grim` says the compositor
  has no `wlr-screencopy`, and the portal would put a dialog in front of the user. So "the icon
  registered with the watcher" is the most that could be confirmed; nobody saw it.
- [local] A throwaway unit with the service's kill mode and without the display:
  `systemd-run --user --unit=motherapp-traytest --collect -p KillMode=mixed
  -p UnsetEnvironment="WAYLAND_DISPLAY DISPLAY" -E XDG_CONFIG_HOME=… -E XDG_STATE_HOME=…
  -E MOTHERAPP_NOTIFY=off <node> core/src/main.ts`. After `kill -9` of its main PID the helper
  was gone and the item unregistered. Outside systemd the same kill also leaves nothing, because
  the helper quits when its stdin closes.
- [both] A check item reports a click through its own `toggled` signal, and setting it from the
  core fires the same signal. → The helper blocks its handler while it applies the core's
  value, and the core re-sends the view after every `mute` event, even an unchanged one, so a
  failed save puts the tick back.
- [both] The tool list alone makes the icon blink: a crashing tool goes `down` → `starting` →
  `down`. → `ToolHealth` keeps a tool "in trouble" from `down`/`failed` until `running` (or
  disabled).
- [both] `install.sh`'s new `tray-icon` row looks at files under `$ROOT` (`/usr/bin/python3`,
  `dist-packages/gi`, the two typelibs) and starts nothing, so `scripts/test-install.sh` stays
  hermetic; `new_case` creates those files, or every case would gain a warning (see the
  `bin-no-node` count in the notification-service entry).
- [both] Tests that fake a `Manager` for `startServer` (`core/test/updater.test.ts`,
  `version.test.ts`) need each thing the server subscribes to; they gained
  `tray: { onChange }`.
- [both] Node's type stripping rejects constructor parameter properties
  (`constructor(readonly x: string)`): "not supported in strip-only mode". Declare the fields.

## Open

- Nobody has seen the icon or its warning variant on the panel; how the 512 px PNG looks at
  panel size (dash-to-panel) was judged only from a 24 px downscale.
- "Open motherapp" was run for real only with a stand-in `xdg-open` (it got the URL, in a scope
  of its own); no browser was opened.
- The real service still runs the old code: the icon appears after the next
  `motherapp install` / restart. Login order (unit before GNOME Shell and the extension) relies
  on libayatana registering once the watcher appears; not tried across a real login.
- The web Settings page has no "Show tray icon" row yet (`tray.get`, `tray.setEnabled`, push `tray`).
- `tools/tmux/test/e2e.test.ts` and the other tools' e2e tests rely on `NODE_TEST_CONTEXT` to keep
  the tray off; only `core/test/e2e.test.ts` also says `MOTHERAPP_TRAY=off`.
