# Bootstrap 6 restyle (2026-10-20, sub-agent: web UI restyle for issue #9)

Restyled the shell, every declarative widget, Logs and Settings with `bootstrap@6.0.0-alpha.1`
(pinned exactly) compiled from Sass by Vite. No Bootstrap JS. Before/after screenshots are in
`docs/screenshots/bootstrap6/`.

## Lessons

- [both] **Compiling Bootstrap 6's Sass yourself gives unprefixed custom properties**, and its
  `fg`/`bg` utilities register `@property --fg` and `@property --bg` with `inherits: false`.
  That breaks the shell's own `--fg`/`--bg` theme variables, which custom pages read from
  nested elements. v6 removed the `$prefix` Sass option ("use PostCSS"). → `web/vite.config.ts`
  has a ~20-line PostCSS plugin that renames Bootstrap's properties to `--bs-*`, the way the
  dist CSS does, and skips everything inside `@layer custom`, where our own rules live. In
  `styles.scss`, inside `@layer custom`, write Bootstrap tokens as `var(--bs-…)`.
- [both] Vite 8 minifies CSS with lightningcss, and with `build.target: "es2022"` it rewrote
  every `light-dark()` into a `--lightningcss-light/dark` polyfill (~20 KB more). → Set
  `build.cssTarget` to browsers that have `light-dark()` (Chrome/Edge 123, Firefox 120,
  Safari 17.5). Bootstrap 6 needs `oklch()`/`color-mix()` anyway.
- [cloud] v6 markup differs from v5 in ways memory gets wrong: `.form-range` is now a
  **wrapper** around `input.form-range-input`, and the filled part of the track comes from
  `--range-fill` (0…1), which Bootstrap's range JS sets. Without the JS, set `--bs-range-fill`
  yourself (the renderer does). `.radio` goes **on the input**; `.switch` is a wrapper `div`;
  `modal` is now `dialog` on a native `<dialog>` with `.dialog-body`/`.dialog-footer`;
  `.form-select` is gone (`form-control` on the `<select>`). Check class names in
  `node_modules/bootstrap/scss/`, not from memory.
- [cloud] `.dialog` is `visibility: hidden` until `[open]`, and `:root.dialog-open` is its scroll
  lock. Our own ~20 lines (`showModal()`, focus Cancel, Escape = cancel) were enough; Bootstrap's
  dialog JS wasn't needed.
- [both] Bootstrap's dark select caret is only swapped under `[data-bs-theme="dark"]`, not for
  the OS setting, so in OS dark mode the caret is dark on dark. → One override in
  `styles.scss` under `prefers-color-scheme: dark`.
- [cloud] npm installs Bootstrap's peer dependencies (`@floating-ui/dom`,
  `vanilla-calendar-pro`) into `node_modules` and the lockfile even though `web/package.json`
  doesn't list them. They aren't imported, so nothing of them is bundled.
- [cloud] Reboot sets `scrollbar-gutter: stable` on `:root`, so headless screenshots show an
  empty strip on the right. Harmless.
- [cloud] `pkill -f 'core/src/main.ts'` in a Bash tool call kills the tool's own shell (exit
  144), because the pattern is in its command line. → `pgrep -f 'node.*core/src/main' | xargs kill`
  in a separate call.
- [cloud] The scratchpad directory is shared with the parallel brightness agent (see its
  entry), so a log named `verify.log` showed its test count (149) instead of mine (107). →
  Unique scratch file names.
- [cloud] Screenshots: run the core with `MOTHERAPP_WEB_DIR` pointing at a copy of the old
  `web/dist` for "before" and at the new build for "after", the fake `pw-dump`/`wpctl` and
  `ddcutil` first on PATH (as the tools' e2e tests do), `TMUX_TMPDIR` set to a short
  `/tmp/…` directory (a long path gives "File name too long" for the socket), and Playwright
  from `/opt/node-tools/node_modules/playwright` with `executablePath: "/opt/pw-browsers/chromium"`.

## Open

- Nothing was looked at in Firefox or on the machine. Check the switch, range, radio and the
  dialog backdrop blur in Firefox on Ubuntu 24.04, and that the page follows a GNOME
  light/dark switch live.
- Bootstrap's font stack omits `system-ui` (on purpose, see the comment in its `_root.scss`), so
  the UI probably no longer uses the Ubuntu font but whatever of Noto Sans / Liberation Sans is
  installed. Easy to change through `$root-tokens` if the user prefers the system font.
- Body text went from 14 px to Bootstrap's 16 px, so pages are taller.
