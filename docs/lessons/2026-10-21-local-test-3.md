# Third local test run, #21 Parts H–N (2026-10-21, local tester)

Ran what didn't need the user from #21 (H–K) and its addenda (L, M, N) on build `v1-613d6c5`.
Results are in the comment on #21; bugs are #26–#29. Nothing was restarted, because a restart
replaces the quick tunnel and the cloud's fresh inbox link would stop working.

## Lessons

- [local] `strace -p <core pid>` fails: `kernel.yama.ptrace_scope` is 1, so only descendants can
  be traced without sudo. → Poll the unit's cgroup instead: read
  `/sys/fs/cgroup/user.slice/user-1000.slice/user@1000.service/app.slice/motherapp.service/cgroup.procs`
  every 1 ms (about 900 polls/s in Python) and print each new pid's `/proc/<pid>/cmdline`. It
  caught every 2 s `tmux` and 3 s `dconf`/`gsettings` spawn. Results: 0 spawns in 30 s with no
  page open; on opening a page the first spawn came 5–17 ms later; `unwatched` 5.0 s after
  hiding the tab; the next spawn right after showing it again.
- [local] **The "GET / every 10 s" from the #16 probe is the user's own `portgate`**
  (`/usr/local/bin/portgate start`, `~/Desktop/projects/portgate`). It scans the local
  listening ports every 10 s (`NewScanner(10*time.Second, …)`) and GETs `/` for the `<title>`.
  It hits 7323, 7324 (the inbox listener), cloudflared's metrics port and everything else.
  cloudflared's `/metrics` (`cloudflared_tunnel_total_requests` on 127.0.0.1:20241 here) didn't
  move, so none of it came through the tunnel. → Don't read periodic local hits as cloud traffic.
- [local] A restart (`make restart`, `motherapp install` with something new) replaces the quick
  tunnel, so the cloud's inbox link dies. → On a test run while the cloud holds a link, prove
  "survives a restart" from earlier restarts. For example, `config.json` mtime 23:35:19 against
  `ActiveEnterTimestamp` 23:35:21 and `/api/status` listing that same order proves M.3.
- [local] **I set the user's real output to 150 %.** I ran `audioctl volume 151` expecting a
  usage error (exit 2), but values above 150 are clamped and applied (#28). → Never probe a
  setter's edge values on real devices. Read the parser first, and only run usage-error checks
  whose rejection you have seen in the code (`mute bogus`, `volume bogus`).
- [local] To run a CLI the way a GNOME shortcut does, copy the environment of
  `gsd-media-keys` (`/proc/$(pgrep -x gsd-media-keys)/environ`). It has the full PATH,
  `XDG_RUNTIME_DIR`, `DBUS_SESSION_BUS_ADDRESS` and `LANG=en_US.UTF-8`, so the earlier
  `env -i PATH=/usr/bin:/bin` emulation was stricter than reality. Under it, `motherapp`
  status/version/logs work. With no `XDG_RUNTIME_DIR` at all, `motherapp status` prints "running
  not running" even though `/api/status` answers, because it asks the API only when systemctl
  says active. That can't happen from a GNOME session.
- [local] The real Claude Code screen (`inboxctl screen motherapp:0.0`, taken while the parent
  session waited for this agent) has the prompt `❯`, not `>`. Under the box are 7+ lines: cwd,
  model and context, branch, permission mode, and the list of agents. Above it is "✻ Waiting
  for 1 background agent to finish". The detector says `no-prompt-line`, as in #22. It would
  also fail `too-many-lines-below` (≤ 4). The screen stays in the 0600 state dir, not the repo,
  because it holds the user's session.
- [local] Playwright 1.63 from the npx cache (`~/.npm/_npx/6bcb61ec6d5aea22/node_modules`) runs
  its matching `chromium-1243` against the real service. The cached `firefox-1509` doesn't match
  1.63's 1543, so Firefox checks stay with the user. To restore config after UI tests, send
  `{"jsonrpc":"2.0","id":1,"method":"tools.setOrder","params":{"order":[…]}}` over `/ws`. The
  file came back byte-identical in content.
- [local] `*.tmp` is gitignored, so an untracked `foo.tmp` doesn't count as a local change for
  `motherapp install`. Use a tracked edit to test the refusal.
- [both] Plan steps that didn't match the code (not bugs): H.5 says `motherapp install` runs
  `--yes --allow-removals`, but 7fef725 dropped `--allow-removals`. For M.5, enabling Demo
  keeps its place (alphabetical after a reset, its saved slot otherwise), per #20's rule
  "disabled tools keep their place"; only a newly installed tool goes at the end. For K.8,
  `grep -c '/inbox/'` matches the "inbox screen saved" path (`…/inbox/screens/…`), not a URL.
  No token or token hash is in the journal or `log.jsonl`. Tunnel host names are logged, by
  design.
