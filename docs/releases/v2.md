# motherapp v2

The first published release. Builds before it called themselves `v1-<hash>`, but v1 was never
tagged, so this covers everything so far. A locally served control panel for an Ubuntu 24.04
GNOME desktop: a systemd user service with a web UI on `http://127.0.0.1:7323/`.

## Install

```sh
bash -c "$(curl -fsSL https://raw.githubusercontent.com/erkantaylan/motherapp/main/scripts/get.sh)"
```

It clones into `~/.local/share/motherapp` (or `MOTHERAPP_DIR`) and runs `./install.sh`, which
asks before every sudo/apt step. To update an install: `motherapp install`, or Settings → Update now.

## What's in it

- **Core and log service.** A generic manager that finds `tools/*/manifest.json`, runs each
  tool's `serve` process with crash backoff, caches state and serves HTTP + WebSocket on
  127.0.0.1. A core log service, with a Logs page and `journalctl`, that every tool uses.
- **Audio** (`audioctl`). Device switching, with devices named by `node.description`. L/R test,
  live mic meter, record-and-playback. Master volume and mute for the default output and mic.
  Per-app volume and mute, one row per app.
- **Brightness** (`brightctl`). One slider per monitor plus a linked "all monitors" slider. Uses
  libddcutil kept loaded through koffi, falling back to the `ddcutil` command. Nothing moves
  while a write is in flight.
- **tmux** (`tmuxctl`). Sessions, with copy and kill-with-confirm.
- **Shortcuts** (`shortcutsctl`). motherapp's own GNOME custom keybindings, with key capture
  and collapsible groups.
- **Inbox** (`inboxctl`). Messages from a cloud Claude session typed into a local tmux pane,
  through a cloudflared quick tunnel. Links have a label and an expiry, tokens are hashed, and
  rate and size limits are fixed.
- **UI.** Restyled with Bootstrap 6 (alpha, pinned). Status dots: setting, then set (fades), or
  failed (stays). The page stays still while you drag a slider.
- **Installer and the `motherapp` command.** `install.sh` checks every dependency and offers
  fixes, asking before each one. For Node 24 it tries nvm/fnm first, and NodeSource only after
  showing what that install would remove. It never removes packages unattended. It writes
  `~/.local/bin` wrappers for every tool and for `motherapp` (`install`/`update`, `status`,
  `version`, `check`, `logs`, `open`, `uninstall`). Versions look like `v<N>-<hash>[-dirty]`.
- **Tool order.** Drag tools into your order on Settings (or use the arrow keys). Every tab's
  sidebar follows.
- **Demand-driven polling.** Tools poll only while a visible page is watching them.
- **Releases and updates (new in this release).** The one-line install. The core checks GitHub
  for the latest release: the sidebar shows "· v3 available" when one is newer, and you can
  turn the check off with `updateCheck: false` in `config.json`. Settings → Update now runs
  `motherapp install` outside the service and follows it through the restart.
